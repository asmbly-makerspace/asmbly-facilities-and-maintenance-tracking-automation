## Implementation details

### layer: `layers/common/python/common/brand.py`

No imports at all; the standard library would be allowed. Module docstring: what it holds,
which pages use it and through which markers, that a change here reaches both pages on
the next deploy (a new layer version, which updates every function that uses the common
layer), and that it must stay standard-library only, so that a page's function can use it
with the common layer and no other (no `requests` layer, no boto3 loaded). Don't write
that the photo page function has the layer: it doesn't until phase 2, which can name it
then.

```python
BRAND_TOKENS_MARKER = "/* __BRAND_TOKENS__ */"
ASMBLY_LOGO_MARKER = "<!-- __ASMBLY_LOGO__ -->"

# The shared design tokens, as CSS declarations for a page's :root block. The first line has
# no indentation (the marker it replaces is indented), later lines four spaces, no trailing
# newline.
BRAND_TOKENS = """/* Shared brand tokens, from layers/common/python/common/brand.py. */

    /* Brand colours (Asmbly brand guide). */
    --asmbly-purple: #292D6A;
    --asmbly-white: #F2F4EF;
    --midnight-black: #171d1a;
    --ceramics: #b34a9a;
    --lasers: #D33E43;

    /* Derived, per sRGB channel, rounded: shade(p) = p × colour + (1 − p) × midnight-black;
       tint(p) = p × colour + (1 − p) × asmbly-white. A test recomputes each. */
    --lasers-shade: #ad373b;
    --lasers-20: #ecd0cd;

    /* Type: system stacks, no font file is fetched. PP Gosha Bold, the brand's heading
       face, isn't loaded until Asmbly confirms its web licence covers these pages. */
    --font-body: Roboto, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", Helvetica, Arial, sans-serif;
    --font-heading: "Helvetica Neue", "Segoe UI", Roboto, Arial, system-ui, sans-serif;
    --font-mono: ui-monospace, SFMono-Regular, Menlo, Consolas, monospace;
    --font-size-body: 1rem;
    --font-size-h1: 1.75rem;
    --font-size-h2: 1.25rem;
    --font-size-small: 0.875rem;
    --line-height: 1.5;
    --line-height-heading: 1.2;
    --weight-heading: 700;
    --weight-strong: 600;

    /* Space and size. */
    --space-1: 0.25rem;
    --space-2: 0.5rem;
    --space-3: 0.75rem;
    --space-4: 1rem;
    --space-5: 1.5rem;
    --space-6: 2rem;
    --gutter: var(--space-4);
    --radius: var(--space-2);
    --logo-height: 3.5rem;
    --border-width: 1px;
    --border-width-accent: 4px;
    --focus-width: 3px;
    --focus-offset: 2px;
    --tap-target: 2.75rem;"""

# The official Asmbly logo (asmbly-makerspace/asmbly-classes,
# app/src/lib/components/logo.svelte at 9a534a6c538df1e602fead183e30d93d97c247b4), inline.
# Its colour comes from the page's CSS (.logo { fill: currentColor; }).
ASMBLY_LOGO = """<svg class="logo" role="img" aria-label="Asmbly Makerspace" viewBox="0 0 443.61 122.16" focusable="false">
      <path d="…"/>   # the 17 <path> lines, copied byte for byte from the stage page.html
      …
    </svg>"""


def fill_brand(page: str) -> str:
    """`page` with BRAND_TOKENS in place of its token marker and ASMBLY_LOGO in place of its logo marker.

    The token marker must appear exactly once; the logo marker at most once (a page may
    have no logo). Raises ValueError otherwise, naming the marker and the count. Reads
    BRAND_TOKENS and ASMBLY_LOGO when called, so a changed value reaches every page that
    fills itself afterwards.
    """
```

- Values: every token value above is copied from the stage `page.html` files. The test
  `test_shared_tokens_match_both_pages` (below) is what proves they match, not this listing.
- `ASMBLY_LOGO`: the opening tag, then the 17 `<path d="…"/>` lines copied from
  `functions/classes/class_photo_upload_page/page.html` lines 259–275 (each indented six
  spaces), then `    </svg>`. With the photo page's marker indented four spaces, phase 2
  serves that page's logo byte for byte as it is today.
- The `ValueError` messages: `"page must have exactly one /* __BRAND_TOKENS__ */ marker,
  found N"` and `"page must have at most one <!-- __ASMBLY_LOGO__ --> marker, found N"`.
  They hold no page content.
- Signature types: `fill_brand(page: str) -> str`; module constants are `str`.

No page imports the module in this phase. Adding it publishes a new layer version on the
next stage deploy, with no change in behavior.

### lambda (tests): the capture script, `tests/capture_page_pins.py`

Added by prep. A capture command kept only in this plan would stop working: it names
6fd11c9, after phase 2 the raw `page.html` no longer holds the 32 shared tokens, and the
plan folder moves to `DONE/` when the plan finishes. So the repository keeps a script that
captures what each page **serves**, and every docstring and README points at it.

Test code in `tests/` (no template packages that folder). Typed, `logging` with lazy
arguments, no `print`, no `git`:

- Module docstring: what the pins are, and that after a deliberate change to a page's
  look you run `.venv/bin/python -m tests.capture_page_pins` from the repository root and
  commit the regenerated fixtures with the change.
- `PAGES: dict[str, tuple[str, re.Pattern[str]]]`: `"kiln"` →
  (`"functions/ceramics/kiln_dropoff_recent_entries_viewer"`, `<style>(.*?)</style>`),
  `"photo"` → (`"functions/classes/class_photo_upload_page"`,
  `<style nonce="__CSP_NONCE__">(.*?)</style>`). Every page-keyed dict in this phase uses
  the keys `"kiln"` and `"photo"`.
- `pinned_tokens_text(sheet: page_style.Stylesheet) -> str`:
  `json.dumps(sheet.tokens(), indent=2, ensure_ascii=False, sort_keys=True) + "\n"`.
  Sorted, so the order of the `:root` declarations (which phase 2 changes) doesn't change
  the file.
- `pinned_rules_text(sheet: page_style.Stylesheet) -> str`: the lines of
  `sheet.rules_after_root()`, right-stripped, blank lines dropped, joined with `"\n"`,
  plus a final `"\n"`.
- `served_sheets() -> dict[str, page_style.Stylesheet]`: kiln `PAGE_TEMPLATE` and photo
  `_template()`, each read with its `PAGES` pattern. It imports the two `lambda_function`
  modules inside the function, so importing the script doesn't import both pages.
- `main() -> None`: puts `layers/common/python` (absolute) on `sys.path` as `pytest.ini`
  does for the tests, because the kiln function imports `common.aws`; writes
  `pinned_tokens.json` and `pinned_rules.css` into each page's `tests/fixtures/`; logs
  each page's token and rule-line counts. `if __name__ == "__main__": main()`.

### lambda (tests): the one-time capture from 6fd11c9

Run it once from the repository root, after writing the script and before the pin tests.
It reads the pages from the commit, not the working tree, so the pins are `stage` as it was
before this plan, and it writes them through the script's own formatters:

```bash
.venv/bin/python - <<'EOF'
import pathlib, subprocess
from tests import capture_page_pins, page_style

for name, (folder, block) in capture_page_pins.PAGES.items():
    html = subprocess.run(["git", "show", f"6fd11c9:{folder}/page.html"],
                          capture_output=True, text=True, check=True).stdout
    sheet = page_style.Stylesheet.from_page(html, block)
    out = pathlib.Path(folder, "tests", "fixtures")
    (out / "pinned_tokens.json").write_text(capture_page_pins.pinned_tokens_text(sheet), encoding="utf-8")
    (out / "pinned_rules.css").write_text(capture_page_pins.pinned_rules_text(sheet), encoding="utf-8")
    print(name, len(sheet.tokens()), "tokens,", capture_page_pins.pinned_rules_text(sheet).count("\n"), "rule lines")
EOF
```

Expected: kiln 54 tokens and 39 rule lines, photo 79 tokens and 105 rule lines. Then
check that the committed script agrees with it on the unchanged pages:
`git diff --quiet 6fd11c9 -- functions/ceramics/kiln_dropoff_recent_entries_viewer/page.html functions/classes/class_photo_upload_page/page.html`
(the pages are as on stage), then `.venv/bin/python -m tests.capture_page_pins` and
`git diff --exit-code -- '*/tests/fixtures/pinned_*'` (it rewrote the same bytes).

No test calls `git`: CI checks out with depth 1, so 6fd11c9 isn't there.

### lambda (tests): the pins in each page's test file

Each test file gets two tests, next to its other style tests, and imports
`from tests import capture_page_pins`. They compare what the page **serves**, not what
`page.html` holds.

- **Kiln:** for each page in `_pages()` (empty, tasks, error), the stylesheet is
  `page_style.Stylesheet.from_page(page, STYLE_BLOCK)`.
- **Photo:** the stylesheet comes from `_call(_event())["body"]`, read with
  `re.compile(r'<style nonce="[A-Za-z0-9_-]+">(.*?)</style>', re.S)`, because the nonce
  has been filled in.
- The rules are normalized with `capture_page_pins.pinned_rules_text(sheet)`, so the
  normalization is defined once.

| Test | Proves |
| --- | --- |
| `test_served_tokens_are_the_stage_tokens` | The served `:root` tokens, as a dict, equal `json.loads` of `fixtures/pinned_tokens.json`, and the `:root` block declares `color-scheme: light`. Story criterion 3: "the served token names and values … are the same as before (a test pins them)". |
| `test_served_rules_are_the_stage_rules` | `capture_page_pins.pinned_rules_text(sheet)` equals `fixtures/pinned_rules.css`. Story criterion 3: "… and the CSS rules are the same as before". |

Each docstring says that the fixtures are `stage` 6fd11c9 from before story #138, and
that a deliberate change to the page's look regenerates them with
`.venv/bin/python -m tests.capture_page_pins`, committed with the change. Each README's
Testing sentence says the same.

### lambda (tests): `tests/test_shared_brand.py`

Module docstring: tests that span both pages and `common.brand`. Imports `common.brand`,
`tests.page_style`, `tests.capture_page_pins`, and both pages' `lambda_function` modules
(the photo page's as `photo`, the kiln's as `kiln`).

- **Helpers.** Every page-keyed dict uses the keys `"kiln"` and `"photo"`.
  - `_served_sheets() -> dict[str, page_style.Stylesheet]` returns
    `capture_page_pins.served_sheets()`: kiln `kiln.PAGE_TEMPLATE`, read with
    `<style>(.*?)</style>`; photo `photo._template()`, read with
    `<style nonce="__CSP_NONCE__">(.*?)</style>`.
  - `_brand_tokens() -> dict[str, str]` is
    `page_style.Stylesheet(":root { " + brand.BRAND_TOKENS + " }").tokens()`.
- `PAGE_ROLE_TOKENS = {"--page-bg", "--text", "--glyph-error"}`, with a comment: the same
  on both pages, kept by each page as its own (README Decision 4).
- `PINNED` maps each page to its `pinned_tokens.json`, loaded with `json.loads`.

| Test | Proves |
| --- | --- |
| `test_shared_tokens_match_both_pages` | Every token in `BRAND_TOKENS` is served by both pages with the same value: `served[name] == value` for each of the 32. Proves the module holds what the pages serve, before and after phase 2. |
| `test_shared_tokens_are_the_story_list` | Every name that both pinned fixtures hold with the same value is either in `BRAND_TOKENS` or in `PAGE_ROLE_TOKENS`, and the two sets are disjoint. `len(_brand_tokens()) == 32`, with none defined twice in `BRAND_TOKENS`. Pins Decision 4. |
| `test_logo_matches_both_pages` | `page_style.logo_problems(page_style.find_logo(brand.ASMBLY_LOGO)) == []`. For each served shell, `" ".join(find_logo(shell).split())` equals the same normalization of `find_logo(brand.ASMBLY_LOGO)`. |
| `test_capture_script_reproduces_the_fixtures` | For each page, `capture_page_pins.pinned_tokens_text` and `pinned_rules_text` of the served shell equal the committed `pinned_tokens.json` and `pinned_rules.css` byte for byte. The script and the fixtures agree, so the script a person runs later writes the same format, and a hand-edited fixture fails. Added by prep. |
